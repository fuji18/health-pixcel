# タスクリスト

## 🚨 タスク完全完了の原則

**このファイルの全タスクが完了するまで作業を継続すること**

### 必須ルール
- **全てのタスクを`[x]`にすること**
- 「時間の都合により別タスクとして実施予定」は禁止
- 「実装が複雑すぎるため後回し」は禁止
- 未完了タスク（`[ ]`）を残したまま作業を終了しない

### タスクスキップが許可される唯一のケース
以下の技術的理由に該当する場合のみスキップ可能:
- 実装方針の変更により、機能自体が不要になった
- アーキテクチャ変更により、別の実装方法に置き換わった
- 依存関係の変更により、タスクが実行不可能になった

スキップ時は必ず理由を明記:
```markdown
- [x] ~~タスク名~~（実装方針変更により不要: 具体的な技術的理由）
```

## 申し送り

### CI 実測(PR #37、2026-10-12、run 38218822811)

| 項目 | MB | バイト |
|---|---:|---:|
| APK 全体(fat) | 50.3 | 52736754 |
| arm64-v8a 相当 | 18.2 | 19064214 |
| Dart AOT(arm64-v8a / armeabi-v7a / x86_64) | 5.4 / 5.9 / 5.5 | 5637000 / 6226504 / 5768072 |
| Flutter エンジン(arm64-v8a / armeabi-v7a / x86_64) | 11.2 / 8.2 / 12.4 | 11747864 / 8615900 / 13051424 |
| その他ネイティブ(3 ABI 合計) | 0.0 | 17752 |
| Flutter アセット | 0.1 | 107597 |
| DEX | 1.1 | 1171552 |
| リソース | 0.2 | 217457 |
| その他 | 0.0 | 21906 |

- fat APK の 94% がネイティブライブラリ(3 ABI 分)。Flutter エンジンだけで 31.8MB あり、アプリ側で減らせない。30MB の目安は fat APK では最初から満たせない値だった
- 依存で増えるのは主に Dart AOT(ABI ごとに約 5.5MB)と DEX。#21 の fl_chart は fat で +0.7MB(ABI あたり約 0.2MB)
- 目安は arm64-v8a 相当で 20MB(実測 18.2MB + 約 10%)とした。数個の依存追加では超えず、大きな SDK(数 MB 級)の混入なら超える幅

### 実装の結果

- 実装は `implement-ticket`(Sonnet fork)で 2 往復。1 回目でフェーズ1・2 を完了し、2 回目は検収の Should 4 件(実行ビット、検査不能を exit 2 に寄せる、unzip の入手性)を反映した。design.md との差異は内部の中間出力のキー欄だけ(空欄で列がずれるため `-` にした)
- 検収(code-reviewer)は Must 0 / Should 4 / Nit 4。Should はすべて反映した
- 目安は初期値 25MB を CI 実測(18.2MB)を見て 20MB に下げた。フェーズ3 の `BUDGET_MB`・`CLAUDE.md` の変更は司令塔が行うため、tasklist に `<!-- main-edit-ok -->` を置いた

### 次回への改善提案

- 実測が要る数値(目安・しきい値)は、design.md で「仮の値」と明記し、測定後に司令塔が直すタスクを最初から tasklist に入れておくと往復にならない(今回はそうした)
- 検収の観点「終了コードの意味が CI でどう解釈されるか」(set -e による想定外の 1 が警告に化ける)は、終了コードで意味を分けるスクリプトを書くときに design.md の段階で書いておく
- devcontainer の python3 は `shutil` が欠けていて `zipfile` が使えない。検証手順に python を指定しない(`zip` コマンドを使う)
- `main-edit-ok` の印は**正確に `<!-- main-edit-ok -->`** と書く(注釈を同じコメントに入れると hook が認識しない)
