# 要求内容

Issue: #26 [チケット] 運動記録の読み取りと表示(P1 / フェーズ 4 / depends: #24)

## 背景・目的

PRD P1「心拍・体重・運動記録の読み取りと表示」のうち運動記録。#24 / #25 の横展開。ただし運動記録は区間を持つ記録(`ExerciseSessionRecord`)なので、睡眠(A3)と同じく「1 件の記録を丸ごと 1 日に帰属させる」判定がドメイン層に要る。

## スコープ(やること)

- **先に** PRD「セキュリティ・プライバシー」に追加する権限の理由を追記する(司令塔が実施済み: コミット e9d0fc8)
- `AndroidManifest.xml` に `READ_EXERCISE` / `READ_DISTANCE` / `READ_TOTAL_CALORIES_BURNED` を追加し、`scripts/check-release-permissions.sh` の許可リストを更新する
  - 距離・消費カロリーは表示しない。`health` 13.3.2 が運動記録の読み取り時にこれらを権限確認なしで読み、未許可だと空の結果を返すため、読み取りの前提として要る(ユーザー決定 2026-10-12。経緯は PRD と design.md「前提」)
- 運動記録を日別の合計時間で表示する(帰属日は開始日。design.md で定める)

## スコープ外(やらないこと)

- 運動の種類別の内訳・消費カロリー・距離・ルート(位置情報)の表示
- 運動時間の目標・グラフ
- 書き込み元が異なる重なった運動記録の重複除去(同一の開始・終了時刻のものだけまとめる。睡眠と同じ)

## 受け入れ条件

- [ ] PRD の理由追記が、マニフェスト・許可リストの変更より前のコミットにある
- [ ] 日をまたぐ運動記録の帰属日判定がドメイン層にあり、ユニットテストがある
- [ ] 運動記録だけ未許可でも他のセクションの表示は保たれる
- [ ] 運動記録の値をログに出さない(`check-privacy.sh` が通る)
- [ ] CI のリリースビルドと権限検査が緑
- [ ] 実機で運動記録が表示されることを確認する(ユーザーが Windows 側で実施)
- [ ] `docs/functional-design.md` を更新する

## 根拠

- `docs/product-requirements.md`「セキュリティ・プライバシー(最重要)」
- `docs/functional-design.md` A3(睡眠セッションの帰属日判定)
