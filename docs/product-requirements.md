# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**health-pixcel** - 端末内だけで完結する個人用ヘルスデータ解析アプリ

### プロダクトコンセプト
- **端末内で完結**: 健康データを外部に一切送信しない。リリースビルドに `INTERNET` 権限を持たせず、OS レベルで送信不能を保証する
- **ヘルスコネクトだけを見る**: データ取得元(HUAWEI / Fitbit など)に依存せず、ヘルスコネクトを唯一の入口にする。ウォッチや同期アプリを替えてもアプリは変わらない
- **自分の目的に沿った切り口**: 睡眠改善・運動習慣の定着という自分の目的に合わせて、必要な数字だけをすぐ見られるようにする

### プロダクトビジョン
スマートウォッチで記録した健康データを、自分のスマートフォンの中だけで自由に振り返り・解析できる状態をつくる。
メーカーの標準アプリに閉じた見せ方ではなく、自分が知りたい切り口(睡眠と運動量の関係など)で継続的に健康状態を把握できるようにする。
データは端末の外に出さず、機器やメーカーを乗り換えても仕組みと記録の見方が途切れないことを目指す。

### 目的
- 直近 7 日の歩数と睡眠を、アプリを開いてすぐ確認できるようにする(MVP)
- 睡眠時間・就寝起床リズム・歩数の改善を、日々の確認習慣を通じて後押しする
- 健康データの外部送信をゼロにし、プライバシーリスクを OS レベルで排除する
- データ取得元・端末に依存しない構成にし、将来の Fitbit / iPhone への移行コストを最小化する

### データの流れ(前提)

```
HUAWEI Band 9 → HUAWEIヘルスケア →(Huawei クラウド)→ Health Sync → ヘルスコネクト → health-pixcel(読み取りのみ)
```

health-pixcel が関与するのは最後の「ヘルスコネクト → health-pixcel」のみ。それより上流(Health Sync の設定・同期)はアプリの責務外とする。

## ターゲットユーザー

### プライマリーペルソナ: 開発者本人(個人利用)
- アプリ開発経験あり。Windows + Android Studio + Flutter SDK + Claude Code で開発する
- 使用機器: Google Pixel 10、HUAWEI Band 9
- 現在の課題:
  - 睡眠の質を改善したい、運動を習慣化したい、健康状態を継続的に把握したい
  - HUAWEIヘルスケアの標準画面では、知りたい切り口(睡眠と運動量の関係など)で振り返れない
  - データが HUAWEIヘルスケア内に閉じており、ヘルスコネクトとの公式連携もない
  - クラウド前提の解析サービスにはデータを預けたくない
- 期待する解決策: 自分の健康データを自分の手元で自由に解析できる仕組み。不要な外部送信がないこと
- 将来の変化: iPhone への機種変更、Fitbit へのウォッチ変更の可能性がある
- 想定する 1 日の使い方:
  - 朝起きたらアプリを開き、昨夜の睡眠時間と就寝・起床時刻を確認する
  - 夜にアプリを開き、今日の歩数と直近 7 日の推移をざっと見る

## 成功指標(KPI)

個人利用アプリのため、利用状況のテレメトリは**取らない**(外部送信禁止の方針と一致させる)。測定は本人による確認で行う。

### プライマリーKPI(ユーザー視点)
- **確認習慣**: 開始から 4 週間のうち、アプリを開いて睡眠・歩数を確認した日が 80% 以上(23 日以上)
  - 測定方法: 本人の自己申告(週次で振り返る)
- **平均睡眠時間の改善**: 開始時点の直近 4 週平均に対し、3 か月後の直近 4 週平均が増加している
  - 測定方法: ヘルスコネクトの記録から算出(MVP 時点では HUAWEIヘルスケア側の週平均表示で代替)
- **平均歩数の改善**: 開始時点の直近 4 週平均に対し、3 か月後の直近 4 週平均が増加している
  - 測定方法: 同上
- **就寝・起床時刻のばらつき縮小**: 3 か月後の直近 4 週の就寝時刻・起床時刻の標準偏差が、開始時点より小さい
  - 測定方法: 同上(P2 の解析機能が入るまでは手計算)

### セカンダリーKPI(プロダクト視点)
- **表示の正確さ**: 直近 7 日の日別歩数・睡眠時間が、HUAWEIヘルスケアの表示と一致する(差異が出た場合は原因を特定して記録する)
  - 測定方法: MVP リリース時と以降月 1 回、7 日分を目視で突き合わせる
- **外部送信ゼロ**: リリースビルドの最終マニフェストに `android.permission.INTERNET` が含まれていない
  - 測定方法: リリースビルドごとに `scripts/check-release-permissions.sh`(最終 APK の権限一覧を許可リストと照合)で確認し、リリース前に APK Analyzer で目視する
- **データ取得元非依存**: ヘルスコネクトへの書き込み元を Fitbit 等に変更しても、アプリのコード変更なしで表示される
  - 測定方法: 書き込み元を切り替えた時点で表示を確認(切り替えが起きるまでは、ソースアプリを条件にした分岐がコードに存在しないことで担保)

## 機能要件

### 共通の定義(MVP)

- **日付の区切り**: 端末のタイムゾーンにおけるローカル日付(00:00〜24:00)
- **直近 7 日**: 今日を含む 7 日間(今日 と その前 6 日)
- **歩数の日別値**: その日の 00:00〜24:00 に記録された歩数の合計。複数の書き込み元がある場合の重複除外はヘルスコネクトの集計(aggregate)に任せる
- **睡眠の帰属日**: 睡眠セッションは**終了時刻(起床時刻)のローカル日付**に帰属させる(例: 10/5 23:30〜10/6 6:30 の睡眠は 10/6 の睡眠)
- **睡眠時間**: セッションの終了時刻 − 開始時刻。1 日に複数のセッション(昼寝など)がある場合は、日別の合計睡眠時間と、各セッションの就寝・起床時刻を表示する
- **今日の扱い**: 今日の歩数は表示時点までの途中値として表示する

### コア機能(MVP)

#### F1. ヘルスコネクトの読み取り権限リクエスト

**ユーザーストーリー**:
開発者本人として、健康データを安全に扱うために、歩数と睡眠の読み取り権限だけをアプリに与えたい

**受け入れ条件**:
- [ ] マニフェストで宣言するヘルスコネクト権限が `READ_STEPS` と `READ_SLEEP` の 2 つだけである(書き込み権限・その他のデータ型の権限を宣言しない)
- [ ] 初回起動時、権限が未許可ならヘルスコネクトの権限ダイアログを表示できる
- [ ] 権限の利用目的を説明する画面(ヘルスコネクトが要求する権限理由の表示先)を備えている
- [ ] 権限を許可した直後、アプリを再起動せずに直近 7 日のデータ表示へ進む
- [ ] 2 回目以降の起動では、許可済みであれば権限ダイアログを出さずにデータを表示する

**優先度**: P0(必須)

#### F2. 直近 7 日の歩数を日別に一覧表示

**ユーザーストーリー**:
開発者本人として、運動習慣が続いているかを把握するために、直近 7 日の歩数を日別に一目で見たい

**受け入れ条件**:
- [ ] アプリ起動後、直近 7 日分(7 行)の日別歩数が一覧で表示される
- [ ] 各行に日付(曜日付き)と歩数(3 桁区切り)が表示される
- [ ] 並び順は新しい日が上
- [ ] 記録がない日は 0 ではなく「記録なし」として表示し、行自体は省略しない
- [ ] 表示された日別歩数が、同じ日の HUAWEIヘルスケアの表示と一致する(差異があれば原因を記録する)

**優先度**: P0(必須)

#### F3. 直近 7 日の睡眠を日別に一覧表示

**ユーザーストーリー**:
開発者本人として、睡眠の量とリズムを改善するために、直近 7 日の就寝・起床時刻と睡眠時間を日別に見たい

**受け入れ条件**:
- [ ] 直近 7 日分(7 行)の日別睡眠が一覧で表示される
- [ ] 各行に日付(曜日付き)、就寝時刻、起床時刻(HH:mm)、睡眠時間(「7時間12分」形式)が表示される
- [ ] 就寝が前日の場合でも、帰属日は起床日になる(「共通の定義」に従う)
- [ ] 1 日に複数セッションがある場合、合計睡眠時間と各セッションの就寝・起床時刻が表示される
- [ ] 記録がない日は「記録なし」として表示し、行自体は省略しない
- [ ] 並び順は新しい日が上

**優先度**: P0(必須)

#### F4. 権限未許可・データなし・利用不可時の案内表示

**ユーザーストーリー**:
開発者本人として、データが出ないときに原因と次の行動がすぐ分かるように、状態に応じた案内を見たい

**受け入れ条件**:
- [ ] 権限が未許可(拒否を含む)のとき、理由の説明と「権限を許可する」操作を表示する。操作から権限ダイアログ、またはヘルスコネクトの設定画面へ遷移できる
- [ ] 歩数・睡眠のうち片方だけ許可されている場合、許可された方は表示し、未許可の方にだけ案内を出す
- [ ] 7 日間すべてデータがない場合、「ヘルスコネクトにデータがありません。Health Sync の同期設定を確認してください」相当の案内を表示する
- [ ] ヘルスコネクトが利用できない(未インストール・要更新)場合、その旨と対処を表示し、クラッシュしない
- [ ] データ読み込み中はローディング表示を出す
- [ ] 読み込み失敗時はエラー内容の要約と再読み込み操作を表示する(健康データの値はエラー表示・ログに含めない)

**優先度**: P0(必須)

### 将来的な機能(Post-MVP)

#### P1(重要)
- **心拍・体重・運動記録の読み取りと表示**: 対応する読み取り権限を追加し、日別に表示する
- **週・月単位の期間切り替え**: 7 日固定の表示を、週・月単位で切り替え可能にする
- **グラフによる推移の可視化**: 歩数・睡眠時間の推移をグラフで表示する
- **目標設定と達成状況の表示**: 歩数・睡眠時間の目標を設定し、日別の達成状況を表示する(目標値はアプリ専用領域に保存)

#### P2(できれば)
- **項目をまたいだ解析**: 睡眠時間と前日歩数の関係など
- **睡眠ステージの分析**: 深い睡眠・レム睡眠など(Health Sync 経由で取得できるか要検証)
- **週次の振り返りサマリー**: 1 週間の平均・ばらつき・前週比を表示する
- **iOS(Appleヘルスケア)対応**

## 非機能要件

### パフォーマンス
- 起動から直近 7 日の歩数・睡眠が表示されるまで: Pixel 10 実機で **3 秒以内**(コールドスタート、権限許可済み)
- 再読み込み操作から表示更新まで: 2 秒以内

### ユーザビリティ
- アプリを開いた最初の画面で、スクロールせずに今日を含む直近の歩数・睡眠が確認できる
- 権限未許可・データなし・利用不可・エラーのいずれの状態でも、画面に「何が起きているか」と「次に何をすればよいか」が表示される
- UI は `docs/ui-design-guidelines.md` の基準に従う

### 信頼性
- 同期遅れ・未記録の日・不完全なセッションなど、データの欠損があってもクラッシュせず「記録なし」として表示する
- ヘルスコネクトの API 呼び出しが例外を返しても、アプリはクラッシュせずエラー状態を表示する

### セキュリティ・プライバシー(最重要)
- **リリースビルドの最終マニフェストに `INTERNET` 権限を含めない**。Flutter はデバッグ/プロファイル用マニフェストに `INTERNET` を自動で含めるため、リリースビルドのマージ後マニフェストで確認する(依存パッケージ経由の混入も含めて検査する)
- ヘルスコネクトの権限は、使うデータ型の**読み取りのみ**を宣言する。書き込み権限は宣言しない
- 健康データ(歩数・睡眠時刻・睡眠時間などの値)をログ(`print` / `debugPrint` / logcat)に出力しない
- 共有ストレージ・クラウド・クリップボード・他アプリへの共有(エクスポート)を行わない
- MVP では健康データをアプリ内に保存しない(起動・再読み込みのたびにヘルスコネクトから読む)。P1 以降で保存が必要になった場合は、アプリ専用領域に限定する
- P1(目標設定)で保存するのは**ユーザーが入力した目標値(歩数・睡眠時間の 2 値)だけ**とし、ヘルスコネクトから読んだ健康データは引き続き保存しない。保存先はアプリ専用領域の `shared_preferences` とする(`android:allowBackup="false"` によりクラウドバックアップの対象外)
- 依存パッケージを追加するときは、ネットワーク通信・解析(アナリティクス)SDK を含まないことを確認する

### 移植性・保守性
- ヘルスコネクト(Android 固有)へのアクセスはデータ取得層に閉じ込め、画面・集計ロジックはプラットフォームに依存しない構成にする(将来の Appleヘルスケア対応で差し替え可能にする)
- データの書き込み元アプリ(Health Sync / Fitbit など)を条件にした分岐を持たない

### 動作環境
- 対象: Android(Google Pixel 10 実機)。ヘルスコネクトが OS に統合された Android 14 以降を前提とする
- 開発・検証: Windows + Flutter SDK。検証コマンドは `flutter analyze` / `flutter test` / `flutter build apk --release`

## スコープ外

明示的にスコープ外とする項目:
- ヘルスコネクトへのデータ書き込み
- HUAWEIヘルスケア・Health Sync の設定や同期の制御(アプリはヘルスコネクトに入ったデータを読むだけ)
- サーバー・クラウド連携、アカウント、バックアップ、マルチデバイス同期
- 他者への共有・エクスポート機能
- 通知・リマインダー
- Google Play での一般公開(個人利用のためサイドロード/ローカルインストールで運用)
- MVP における iOS 対応、歩数・睡眠以外のデータ型(P1/P2 に記載)
